# Seguimiento de la fase 4

Registro incremental de la migración MVC al consumo de la API. La fase permanece abierta hasta verificar que Web no conserva almacén propio y que los datos sobreviven al reinicio de Web, pero no al de API.

| Paso | Estado | Evidencia o límite |
| --- | --- | --- |
| F4.1 | Completado | Los cuatro controladores MVC usan `IHttpClientFactory` y acciones asíncronas para sus operaciones de datos. El cliente nombrado `ApiCarniceria` conserva la dirección base configurable y el límite de tres segundos ya registrado. Se usan los contratos `Respuesta*` para lecturas y los formularios compartidos para escrituras. La compilación de `Carniceria.slnx` terminó con 0 errores y 0 advertencias. El humo [`Verificar-Mvc.mjs`](../pruebas/Fase4/Verificar-Mvc.mjs) aprobó 77/77 aserciones. Una prueba dirigida posterior confirmó el cierre del harness y que los puertos 5234/5235 quedaron sin listeners; no fue necesario repetir las 77 aserciones. |
| F4.2 | Completado | El grupo `Rutas` de [`Verificar-Mvc.mjs`](../pruebas/Fase4/Verificar-Mvc.mjs) aprobó 77/77 verificaciones distintas a `Migracion`: lectura de listados/detalles, cancelación de confirmaciones sin mutación, 12 POST sin token antifalsificación rechazados con 400 y cuatro consultas codificadas con caracteres reservados, recibidas por un stub sin filtros locales en Web. La ejecución usó API 5234 y Web 5235 y terminó con ambos puertos sin listeners. No hubo cambios de aplicación ni se repitió el grupo `Migracion` de F4.1. |
| F4.3 | Completado | El grupo `Proveedores` de [`Verificar-Mvc.mjs`](../pruebas/Fase4/Verificar-Mvc.mjs) aprobó 150/150 aserciones: opciones recibidas desde API, selección actual, conservación de formulario ante proveedor requerido o inválido, alta y reasignación conservando el Id del producto, y datos descriptivos actualizados en lista, detalle y búsqueda. La regresión del contrato compartido aprobó además 64/64 verificaciones del grupo `Proveedores` de F3, en una ejecución separada. La ausencia y el valor nulo se rechazan en el ModelState del formulario como solicitud inválida; el `Guid` vacío y la referencia no existente se rechazan como fallos de validación de negocio; todos devuelven 400 y conservan el campo de proveedor. No se repitieron los grupos `Migracion` ni `Rutas`. |
| F4.4 | Completado | `AgregarErroresApi` normaliza claves conocidas de `ErrorApi` a campos del formulario; las claves desconocidas y todos sus mensajes se muestran en el resumen. Cuando el mensaje o la lista de errores son nulos o vacíos, usa un mensaje general no vacío. Se admiten claves JSON como `$.fechaNacimiento` y el prefijo `solicitud.`. Un caso reproducible devolvía 500 antes del cambio por una clave desconocida sin mensajes y `Mensaje: null`; después devolvió 200 y mostró un error general, conservando los valores y opciones del formulario. El cambio se limitó al helper y la solución compiló con 0 errores y 0 advertencias. El grupo `ErroresFormulario` aprobó 256/256 aserciones en 21 contratos, con API 5234 y Web 5235; no se repitieron los grupos anteriores. |
| F4.5 | Completado | El grupo `Mensajes` de [`Verificar-Mvc.mjs`](../pruebas/Fase4/Verificar-Mvc.mjs) aprobó 288/288 aserciones nuevas en los cuatro módulos: PRG solo tras altas 201 válidas, ediciones 200 con DTO/Id válido y bajas 204; mensaje temporal visible en la primera página y ausente en la siguiente; errores y cancelaciones sin flash ni mutación; y baja de proveedor bloqueada con 409 en la misma confirmación y el mismo Id. Se verificaron 8 rechazos 400/409 del servidor conservando los formularios y una sola solicitud de mutación por envío. 404 representa únicamente un recurso ausente. No hubo cambios de aplicación, build ni repetición de los grupos previos. |
| F4.6 | Implementado; auditoría pendiente | Errores de conexión, timeout y respuestas JSON nulas, malformadas o incompletas no se presentan como listas vacías ni como éxitos. Las búsquedas conservan criterio y consulta. Si una mutación ya se envió y no se recibe confirmación, el formulario indica que el resultado es incierto y no reintenta. |

## Límite de la evidencia actual

Los grupos `Migracion`, `Rutas`, `Proveedores`, `ErroresFormulario` y `Mensajes` aprobaron 77, 77, 150, 256 y 288 aserciones MVC distintas (848 en total). La regresión independiente de API F3 `Proveedores` aprobó 64 verificaciones por el cambio compartido de validación. Estas pruebas no cubren la prueba de cultura/interfaz interactiva ni el reinicio aislado de Web y API. La auditoría de F4.6 y la prueba de cultura de F4.7 siguen pendientes. F4.8 y F4.9 no se consideran completados; la eliminación de dependencias Web al almacén y la propiedad única del almacenamiento se comprobarán allí.
