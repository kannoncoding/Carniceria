## Límites y evidencia

- El almacén duplicado de Web es temporal y se mantiene sin cambios hasta F4, cuando sus controladores migren a HTTP.
- F2 no implementa el CRUD completo de API; ese trabajo corresponde a F3.
- La superficie HTTP es deliberadamente mínima; PUT, DELETE, búsquedas y el resto del CRUD pertenecen a F3.
- F2.3 define contratos de las cuatro entidades existentes; los contratos de factura corresponden a F5.
- El formulario compartido de producto permite omitir temporalmente `ProveedorId` para el almacén heredado de Web hasta F4; la API valida la relación estrictamente.
- El almacén singleton de API conserva datos en memoria y reinicia con semillas. Web todavía tiene su almacén heredado; no se afirma propiedad única de los datos en toda la solución hasta la migración de F4.
